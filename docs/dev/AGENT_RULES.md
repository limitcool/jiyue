## Build and test hygiene
- Network works: never use `--offline`. Build/check with `cargo check -p jiyue` (fast) and `cargo build -p jiyue`; test with `cargo test -p jiyue`.
- Other agents edit other files of the same crate at the same time. Keep the crate compiling after EVERY save of yours: write new code into new files first, wire it in with one small edit, run `cargo check -p jiyue` immediately. If the build fails in a file you do not own, `sleep 45` and retry (up to 10 times), then say so in your report; never "fix" someone else's file.
- Never run `target\debug\jiyue.exe` directly (other agents rebuild it): copy it to `dev\<yourname>-run.exe` and run the copy. If the original is locked, use `target\debug\deps\jiyue.exe`.
- Use a SCRATCH COPY of the demo vault for every GUI test (copy D:\dev\rustdian\demo-vault to <scratch>\<yourname>-vault). Never modify the real demo-vault.
- GUI verification = scripted REAL input + screenshots that you READ: dev\interact.ps1 (and interact_md.ps1, interact_widgets.ps1, interact_style.ps1) show how to start the copied exe, send keys/clicks/IME, wait, capture PNGs (PowerShell 7 `pwsh` is required: Windows PowerShell 5.1 misreads Chinese). Copy one to dev\interact_<yourname>.ps1 and adapt. Capture ink and fog themes for visual features. Real IME (pinyin) input must work in any text field you add.
- Visual language: read design\v3\*.png and design\html\*.html; use ActiveTheme tokens only (crates\jiyue-app\src\theme.rs), the shared widgets in crates\jiyue-app\src\ui\widgets\ (LineInput with IME, button, toggle, segmented, select, modal, confirm_dialog, context_menu, form_row ...; see widgets\demo.rs for usage), icons from assets\icons (only those exist; do not add icons: if you need one, list it in the report), all UI text Simplified Chinese.
- Extension hub: crates\jiyue-app\src\ui\ext.rs defines ExtState, ExtCommand, ExtEvent, overlays(), handle_key(), on_event(), palette_commands(), statusbar_items(), toasts (`app.toast(ToastKind, text)`), and jobs.rs has `spawn_blocking`. Your module (ui\<name>_ui.rs) plugs in there. You may create child modules inside your own module file (e.g. ui\search_ui.rs declares `mod panel;` living in ui\search_ui\panel.rs). Do NOT edit ext.rs, main.rs, palette.rs, settings.rs, graph.rs, theme.rs or ui\mod.rs unless your brief lists them as yours (agent W2-0 owns those and is wiring the widgets key bindings first; before you test typing, check that `ui::widgets::bind_keys` appears in main.rs, otherwise wait a few minutes).
- Background work: blocking calls (network, disk scans, indexing) go through `jobs::spawn_blocking` or your own thread + a channel polled by a `cx.spawn` timer; never block the UI thread; never call jiyue-sync/jiyue-ai from inside a tokio runtime.

## General
- Commit messages and PR descriptions never mention Claude or any AI tool: no `Co-Authored-By: Claude ...` trailer, no "Generated with ..." line. This overrides any default attribution a tool suggests. Plain messages only.
- No git commands that change state (no add/commit/checkout/reset/stash). Never `find /` or search the whole disk; gpui sources: D:\cache\cargo\registry\src\index.crates.io-1949cf8c6b5b557f\gpui-0.2.2. Python only D:\venvs\automation\Scripts\python.exe. Always Read a file range right before editing it. rustfmt only your own files. No unwrap/expect/panic on user-controlled data. Unit tests for all pure logic. Report new dependencies (name, version, why).
- Secrets (S3 keys, API keys) must never be printed, logged, or written to the repo. A helper exists that runs a command against the user's real S3-compatible server (RustFS) with env vars JIYUE_TEST_S3_ENDPOINT/_BUCKET/_KEY/_SECRET/_REGION and a fresh versioned test bucket that it deletes afterwards: `D:\venvs\automation\Scripts\python.exe <scratch>\rustfs_run.py -- <command>` (you never see the credentials). Docker is not to be used.
- Final report (short, plain text): what you built, what you verified (with PNG paths) and what you could not verify, files changed, new dependencies, limitations, requests for files you do not own.
